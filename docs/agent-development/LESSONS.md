# OneWeb 任务经验

这是任务复盘产生的候选规则台账，初始没有已证实的 OneWeb 事故条目。开始修改代码时只读与本轮子系统 / 失败模式相关的条目；现行规范仍来自根 `AGENTS.md`、相关 ADR / spec 和隐私清单。

## 记录与提升

1. 完成任务或达到修复上限后，读取该任务的实际 diff、失败日志、评审和最终证据。记录可复现的漏验、返工或成功约束；无证据的猜想标为待核实。
2. 一个条目只表达一个规则。写明触发条件、可观察后果、原因、正确做法、证据路径 / SHA、适用子系统和覆盖缺口；日志使用脱敏材料。
3. `Seen` 只计不同日期的独立观察，记录 ISO 日期及所用时区。同一天重复失败、代理重读或三次重复生成不增加日期数。
4. 同一候选在至少三个不同日期得到证据后，可提议升入对应现行规范。先检查是否已有等价条目，以引用取代复制；涉及产品方向由用户决策，不由计数决定。
5. **三日期只触发候选提升。** 把可机械验证的规则实现为 lint / 契约测试 / 检查，并证明违例失败、正确实现通过，再接入任务或 CI，才称为硬约束。仍依赖审美或判断的规则保留人工评审边界。

## 条目模板

```markdown
### L-001：<触发条件 → 可检查规则>

- 状态：待核实 / 候选 / 待提升 / 文档规范 / 已机械执行
- 适用：<子系统与范围>
- 规则：<一个明确行为>
- 原因：<实际失败或返工的因果>
- 证据：<任务 ID、SHA / diff、失败日志、评审、复验>
- 正确做法：<可执行处理与验收>
- Seen：1 个日期（YYYY-MM-DD；时区 Asia/Shanghai）
- 缺口：<尚未验证的平台 / 场景>
- 提升位置：<现有 ADR / spec / 规范；未提升写无>
- 机械检查：<命令 / 测试路径；违例失败记录；接入位置；尚无写无>
```
